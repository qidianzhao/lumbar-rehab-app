# 腰突康复运动App — 产品需求文档（PRD）

**文档版本：** v1.0  
**日期：** 2026年4月12日  
**角色分工：** 产品经理（AI）+ 独立开发者  
**目标平台：** Android  

---

## 一、产品概述

### 1.1 产品定位

一款专为腰椎间盘突出康复期人群设计的**运动健身类App**，聚焦腰腹核心力量训练，提供AI驱动的个性化训练计划、语音互动跟练、训练记录与数据分析功能。

**关键定位边界：** 本产品定位为运动健身类App，**非医疗类App**。不在App内提供诊疗建议、医学文献查询等医疗功能。AI的专业知识来源（康复指南、运动医学文献）通过云端RAG服务在后端支撑，App前端不暴露任何医学文献或知识库内容。

### 1.2 目标用户

腰椎间盘突出康复期、无明显急性症状的人群，有通过运动健身加强腰腹核心力量的需求，希望获得系统化、个性化的训练指导。

### 1.3 核心价值主张

- **个性化**：通过体能测试评估用户当前水平，生成匹配个人能力的训练计划，而非标准化课程
- **智能互动**：AI语音对话伴练，提供情绪鼓励、动作完成记录、训练节奏引导
- **专业可靠**：训练计划和动作库基于腰椎间盘突出运动康复的权威指南设计（后端知识库支撑）
- **持续追踪**：完整的训练数据记录、阶段性报告生成，可导出供复诊参考

### 1.4 与竞品的差异化

| 维度 | 主流健身App | 平台散点内容 | 本产品 |
|------|------------|-------------|--------|
| 课程定制 | 标准化课程，不区分个体 | 无体系 | 体能测试+AI个性化生成 |
| 薄弱环节识别 | 无 | 无 | 测试评估+针对性补强计划 |
| AI互动 | 无或极简 | 无 | 语音对话伴练 |
| 腰突适配 | 通用健身，含危险动作 | 质量参差 | 禁忌动作过滤+专业动作库 |
| 训练进阶 | 固定难度 | 无体系 | 三阶段进阶+回退机制 |
| 数据导出 | 有限 | 无 | PDF报告，可供复诊使用 |

## 二、用户角色与使用场景

### 2.1 用户画像

- **基本特征**：腰椎间盘突出患者，已度过急性期，日常无明显症状或症状轻微
- **核心需求**：通过系统训练加强腰腹核心力量，预防复发
- **痛点**：不知道哪些动作安全、不知道自己哪里薄弱、缺乏坚持训练的动力和记录
- **突出情况各异**：突出节段（L3/4、L4/5、L5/S1等）、突出类型（膨出、突出、脱出）、是否伴有其他问题（椎管狭窄、滑脱等）

### 2.2 典型使用场景

**场景一：首次使用**  
用户下载App → 阅读并同意免责声明 → 完成基本注册（昵称、性别、年龄） → 系统引导填写个人运动档案（可跳过） → 引导体能测试（可跳过） → 进入App首页。跳过的步骤可在后续任意时间通过"个人中心"或训练入口触发完成。

**场景二：日常训练**  
用户打开App → 训练前状态确认（正常/异常分流） → 进入当日训练课程 → 跟练视频播放+AI语音互动（鼓励、计数、提问） → 训练结束 → 生成本次训练报告 → 打卡

**场景三：症状波动**  
用户训练前选择"今日有不适" → 进入症状记录页面（疼痛部位、程度） → 系统显示安全提示+免责声明 → 推荐降级/急性期安全动作或建议休息

**场景四：阶段性回顾**  
完成一个训练阶段 → 系统生成阶段报告（训练完成率、能力变化、疼痛趋势等） → 用户可导出PDF报告 → 分享到社交平台或带去复诊

### 3.2 M01 — 用户注册与个人运动档案

#### 3.2.1 功能描述

用户首次使用时完成基本注册，并可选择填写个人运动档案，为AI生成个性化训练计划提供基础数据。注册时仅需完成必要信息（昵称、性别、年龄），运动档案、体能测试、训练计划生成等步骤均可跳过，用户可在后续任意时间完成。

#### 3.2.2 功能细项

**注册方式：**
- 手机号+验证码注册/登录
- 支持微信一键登录（可选）

**注册必填信息（不可跳过）：**
- 昵称（用于排行榜展示）
- 性别（影响训练强度推荐）
- 年龄（影响训练强度推荐）

**个人运动档案字段（可跳过，后续在个人中心补充）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 身高 | 数字 | 否 | |
| 体重 | 数字 | 否 | |
| 腰部情况 | 多选 | 否 | L3/4、L4/5、L5/S1、其他、不确定 |
| 腰部情况程度 | 单选 | 否 | 膨出、突出、脱出、不确定 |
| 其他腰部相关情况 | 多选 | 否 | 椎管狭窄、腰椎滑脱、侧弯、无 |
| 日常久坐时长 | 单选 | 否 | <4h、4-8h、>8h |
| 运动习惯 | 单选 | 否 | 无运动习惯、偶尔运动、规律运动 |

**首次注册引导流程：**
1. 完成基本注册（昵称、性别、年龄） → 必须完成
2. 引导填写个人运动档案 → 显示"跳过"按钮，用户可直接跳到下一步
3. 引导进行体能测试 → 显示"跳过"按钮，用户可直接进入首页
4. 若完成了体能测试 → 展示评估结果与训练计划建议 → 用户可确认或稍后再看

**跳过后的引导机制：**
- 首页显示温和提示卡片："完善运动档案，获取更适合你的训练计划"
- 用户首次点击"开始训练"时，若未完成运动档案和体能测试，弹出提示建议先完善（可再次跳过，使用通用初级计划）
- 个人中心提供"运动档案"和"体能测试"入口，随时可补充

**档案修改：** 用户可在"个人中心"随时修改个人运动档案信息，修改后系统提示是否需要重新生成训练计划。

### 3.3 M02 — 免责声明与安全机制

#### 3.3.1 功能描述

在关键节点向用户展示免责声明和安全提示，明确产品的运动健身定位，划清与医疗服务的边界。

#### 3.3.2 功能细项

**免责声明触发时机：**
- 首次注册时（必须阅读并勾选同意方可继续）
- 训练前状态确认为"有不适"时
- 关于页面中常驻展示

**免责声明核心内容：**
- 本App为运动健身辅助工具，不提供医疗诊断或治疗建议
- 训练计划仅供参考，用户应根据自身实际情况决定是否执行
- 急性期、重度突出患者应在专业医生或康复师指导下进行训练
- 使用本App过程中如出现任何不适，应立即停止训练并就医
- 用户确认自愿使用并自行承担训练风险

**训练前状态确认（轻量分流设计）：**
- 每次开始训练前，弹出简洁提问："今天身体状态如何？"
- 选项一："状态正常，开始训练" → 直接进入训练流程
- 选项二："有些不适" → 进入不适记录页面
  - 记录疼痛部位（身体图点选）、疼痛程度（0-10滑块）、症状描述（可选文字输入）
  - 显示安全提示："建议今日休息或仅进行轻度拉伸，如症状持续请及时就医"
  - 附免责声明
  - 提供选项："仍要进行轻度训练（用户自行负责）"或"今日休息"
  - 若选择轻度训练，系统推荐轻度拉伸/放松类动作

**训练中紧急暂停：**
- 训练界面常驻"暂停"按钮，点击后立即暂停视频和AI互动
- 暂停后显示："如感到疼痛或不适，建议立即停止训练"
- 提供"继续训练"和"结束训练"选项

**禁忌动作黑名单：**
- 系统内置腰突患者应避免的动作清单（如仰卧起坐、直腿硬拉、过度前屈、负重深蹲等）
- 这些动作不会出现在任何自动生成的训练计划中
- 禁忌动作列表在"动作库"中有标注和说明，告知用户为何应避免

### 3.4 M03 — 体能测试与评估

#### 3.4.1 功能描述

通过一套标准化测试动作，评估用户当前的核心力量、柔韧性、稳定性等维度，确定训练起点和薄弱环节。

#### 3.4.2 功能细项

**测试流程：**
1. 首次完成个人运动档案后引导进入体能测试（若用户跳过了运动档案，也可直接从个人中心进入体能测试）
2. 系统依次展示测试动作视频，每个动作有标准说明和要求
3. 用户跟做后，通过AI语音对话报告完成情况（完成个数/坚持时长）
4. 全部测试完成后，AI根据数据生成评估报告

**测试动作维度（示例，具体动作由AI基于知识库生成）：**

| 测试维度 | 示例动作 | 测量指标 |
|---------|---------|---------|
| 核心耐力 | 平板支撑 | 坚持时长（秒） |
| 臀部力量 | 臀桥 | 完成次数 |
| 脊柱稳定性 | 鸟狗式 | 完成次数+能否保持稳定 |
| 核心控制 | 死虫式 | 完成次数 |
| 脊柱灵活性 | 猫牛式 | 动作流畅度（自评） |
| 后链柔韧性 | 坐位体前屈 | 可及距离（自评分级） |

**评估输出：**
- 综合评级：初级 / 中级 / 高级
- 各维度得分与雷达图展示
- 薄弱环节分析：指出用户哪些维度较弱，对应哪些肌群需要加强
- 建议起始训练计划等级
- 可选的单独补强训练建议

**重新测试：**
- 用户可随时在"个人中心"发起重新测试
- 系统建议每完成一个训练阶段后重新测试，以评估进步和调整计划
- 多次测试结果保留，可在报告中查看能力变化曲线

### 3.5 M04 — 训练计划管理

#### 3.5.1 功能描述

基于体能测试结果和用户个人运动档案，由AI生成个性化的分阶段训练计划，支持动态调整和回退。

#### 3.5.2 功能细项

**计划层级结构：**

```
训练计划
├── 阶段（初级/中级/高级）
│   ├── 周计划（每周N天训练）
│   │   ├── 日训练课程
│   │   │   ├── 热身阶段（5-8分钟）
│   │   │   ├── 核心训练阶段（15-30分钟）
│   │   │   └── 拉伸放松阶段（5-8分钟）
│   │   │       └── 动作项
│   │   │           ├── 动作名称
│   │   │           ├── 组数
│   │   │           ├── 每组次数/时长
│   │   │           └── 组间休息时间
│   │   └── 休息日
│   └── 阶段目标与完成标准
└── 单独补强计划（可选）
    └── 针对薄弱环节的专项训练
```

**三阶段训练体系：**

| 阶段 | 特点 | 参考周期 | 进阶条件 |
|------|------|---------|---------|
| 初级 | 基础动作、低强度、短时长、重点掌握正确动作模式 | 4-6周 | 完成阶段测试达到中级标准 |
| 中级 | 动作难度提升、增加组数/次数、引入不稳定面训练 | 6-8周 | 完成阶段测试达到高级标准 |
| 高级 | 复合动作、功能性训练、接近正常运动能力 | 持续 | 定期测试维持水平 |

**训练计划特性：**
- 每次训练包含完整的"热身→核心训练→拉伸放松"三段式结构
- 训练频率：根据用户情况推荐，默认每周3-5天
- 用户确认计划后方可开始执行，可要求AI调整
- 支持用户查看每个动作的详细说明，理解为什么安排这个动作

**回退机制：**
- 当用户连续多次训练前反馈不适时，系统主动建议降级训练阶段
- 用户可手动选择降回上一阶段
- 回退后保留之前的训练记录，恢复后可继续

**单独补强计划：**
- 基于体能测试中薄弱环节的分析结果生成
- 可作为主训练计划的补充，独立安排训练时间
- 例如：臀部力量不足 → 提供臀桥变式、蚌式开合等专项训练

### 3.6 M05 — 动作库与视频内容

#### 3.6.1 功能描述

提供经过专业筛选的、适合腰突康复人群的运动动作库，每个动作配有真人示范视频和详细说明。

#### 3.6.2 内容来源

MVP阶段采用自行录制真人示范视频的方案，核心动作库约20-30个动作。

#### 3.6.3 动作数据结构

每个动作包含以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| action_id | 字符串 | 动作唯一标识 |
| name | 字符串 | 动作名称（中文） |
| name_en | 字符串 | 动作英文名称 |
| category | 枚举 | 热身/核心训练/拉伸放松 |
| target_muscle | 数组 | 目标肌群（如腹横肌、多裂肌、臀大肌等） |
| difficulty | 枚举 | 初级/中级/高级 |
| video_url | 字符串 | 视频文件地址（支持离线缓存） |
| video_duration | 整数 | 视频时长（秒） |
| description | 文本 | 动作文字说明 |
| key_points | 数组 | 动作要点提示（如"保持腰椎中立位"） |
| common_mistakes | 数组 | 常见错误（如"塌腰""耸肩"） |
| suitable_segments | 数组 | 适用突出节段 |
| contraindications | 文本 | 禁忌情况说明 |
| is_forbidden | 布尔 | 是否为禁忌动作（仅用于知识展示，不进入训练计划） |
| default_sets | 整数 | 默认组数 |
| default_reps | 字符串 | 默认次数或时长（如"12次"或"30秒"） |
| rest_between_sets | 整数 | 默认组间休息时间（秒） |

#### 3.6.4 MVP阶段核心动作清单（参考）

**热身动作：** 猫牛式、骨盆时钟、仰卧抱膝、站立体侧屈、髋关节环绕

**核心训练动作（初级）：** 臀桥、鸟狗式（对侧手脚伸展）、死虫式、侧卧蚌式开合、麦肯基伸展（俯卧撑式）、仰卧腿交替伸展、四点支撑腹部收紧

**核心训练动作（中级）：** 单腿臀桥、平板支撑、侧平板支撑、鸟狗式（含保持）、反向平板支撑、弹力带蚌式开合、站立单腿支撑

**核心训练动作（高级）：** 臀桥行进、平板支撑变式（对侧手脚抬起）、瑞士球臀桥、弹力带抗旋转、单腿硬拉（轻负重）、农夫行走

**拉伸放松动作：** 婴儿式、仰卧脊柱扭转、梨状肌拉伸、股四头肌拉伸、腘绳肌拉伸、髋屈肌拉伸

注：以上动作清单为参考，实际动作选择需基于云端知识库中的权威康复指南来确认和调整。

### 3.7 M06 — 跟练播放与AI语音互动

#### 3.7.1 功能描述

训练过程中，视频按计划顺序播放，AI通过语音与用户实时互动，提供鼓励、计数、状态询问等功能。

#### 3.7.2 跟练播放流程

```
训练前状态确认（M02）
    ↓ 正常
进入今日训练课程
    ↓
展示今日训练概览（动作列表、预计时长）
    ↓
开始热身阶段
    ↓ 热身动作逐一播放+AI引导
核心训练阶段
    ↓ 每个动作播放 → 组间休息倒计时 → 下一组/下一个动作
    ↓ AI全程语音互动
拉伸放松阶段
    ↓
训练结束
    ↓
生成本次训练报告
    ↓
打卡
```

#### 3.7.3 视频播放器功能

- 全屏/竖屏播放
- 暂停/继续
- 上一个动作/下一个动作（跳过）
- 组间休息倒计时（可自定义时长）
- 动作要点文字悬浮提示（视频上方或下方半透明区域展示）
- 当前进度条（整体训练进度 + 当前动作组数进度）

#### 3.7.4 AI语音互动

**技术实现：** 调用大模型API + TTS（文字转语音）+ ASR（语音识别），通过后端中转服务调用。

**AI互动场景设计：**

| 场景 | AI行为 | 示例话术 |
|------|--------|---------|
| 动作开始时 | 介绍动作要点 | "接下来是臀桥，注意双脚踩实地面，不要塌腰哦" |
| 动作进行中 | 鼓励与节奏引导 | "很好，保持住！""再来3个！" |
| 一组完成时 | 询问完成情况 | "这一组做了几个呀？""完成得怎么样？" |
| 用户回答后 | 记录并鼓励 | "做了10个，不错！休息30秒，准备下一组" |
| 用户表示困难 | 调整与鼓励 | "没关系，做到力竭就好，这已经很棒了" |
| 组间休息 | 提供放松提示 | "休息一下，活动活动手腕脚踝" |
| 训练结束 | 总结与鼓励 | "今天的训练完成了！比上次多做了3个臀桥，继续加油！" |

**AI角色设定（System Prompt核心要点）：**
- 角色：专业友善的运动健身教练
- 语气：温暖、鼓励、专业、不急躁
- 职责范围：仅回答与运动健身训练相关的问题
- 禁止回答：医疗诊断、药物建议、与训练无关的话题
- 关键词触发：当用户表达疼痛、不适时，建议暂停训练并提示就医

**AI记录的数据（每个动作）：**
- 用户报告的完成次数/时长
- 用户反馈的困难程度
- 是否完成了计划的组数
- 训练中的异常反馈（如提到疼痛）

### 3.8 M07 — 训练记录与报告

#### 3.8.1 功能描述

自动记录每次训练数据，生成单次训练报告和阶段性报告。

#### 3.8.2 单次训练报告

每次训练结束后自动生成，包含：
- 训练日期与时长
- 完成的动作列表、每个动作的组数和次数
- 计划完成率（实际完成 / 计划量）
- 训练前状态记录（正常/不适及详情）
- AI互动中的关键记录（如用户反馈困难的动作、中途暂停情况）
- 鼓励语与下次训练预告

#### 3.8.3 阶段性报告

在以下节点触发生成：
- 完成一周训练后（周报告）
- 完成一个训练阶段后（阶段报告）
- 用户手动请求生成

阶段性报告包含：
- 本阶段训练天数与总时长
- 动作完成量变化趋势（折线图）
- 各维度能力变化（与体能测试结果对比的雷达图）
- 打卡连续天数
- 不适记录汇总与趋势
- AI综合评价与下阶段建议
- 关键里程碑（如"平板支撑从30秒提升到60秒"）

#### 3.8.4 数据存储

- 训练记录本地存储（SQLite）+ 云端同步
- 历史记录可无限查看
- 支持按日期、按动作、按阶段筛选查看

### 3.9 M08 — 打卡与排行榜

#### 3.9.1 打卡功能

- 完成当日训练后，系统自动标记打卡

- 显示连续打卡天数和累计打卡天数

#### 3.9.2 排行榜

**排行维度：** 训练天数（打卡天数）

**排行周期：**

- 月榜：本月训练天数排名
- 年度榜：本年度训练天数排名

**展示信息：** 排名、用户昵称、训练天数、连续打卡天数

**隐私保护：** 用户可在设置中选择是否参与排行榜，默认参与。昵称为用户自定义，不展示真实姓名。

### 3.12 M11 — Token用量与安全控制

#### 3.12.1 功能描述

控制大模型API的使用成本，防止滥用，保障系统安全。

#### 3.12.2 Token用量控制

| 控制项 | 策略 |
|-------|------|
| 训练中AI互动 | 仅在训练时段（从开始训练到结束训练期间）可用，每次训练session内不额外限制 |
| 自由问答（非训练时段） | 每用户每日限制10-20次对话（可配置） |
| 单次输入长度 | 限制用户单次输入不超过200字符 |
| 单次输出长度 | 限制AI单次回复token数（控制成本） |
| 异常检测 | 单用户短时间内高频调用时自动触发限流，返回友好提示 |
| 用量提示 | 当日剩余免费对话次数在界面展示 |

#### 3.12.3 Prompt安全

- System Prompt严格限定AI角色为运动健身教练
- 拒绝回答与运动训练无关的问题，返回引导话术："我是你的运动教练，咱们聊聊训练相关的吧~"
- 防Prompt注入：对用户输入进行基本过滤，屏蔽尝试修改System Prompt的指令
- 敏感词过滤：涉及医疗诊断、药物等关键词时，触发标准免责回复

#### 3.12.4 接口安全

- API Key存储在后端服务器，客户端不存储任何Key
- 客户端通过开发者自建的后端中转服务调用大模型API
- 后端实现接口鉴权（Token认证）
- 接口频率限制（Rate Limiting）
- 请求日志记录，便于监控异常

#### 3.12.5 数据安全

- 用户个人运动档案、训练记录加密存储（本地AES加密 + 传输HTTPS）
- 用户数据不用于任何第三方分享或商业用途
- 隐私政策明确告知数据收集范围、存储方式、使用目的
- 用户可申请导出或删除个人数据

              │

### 4.2 关键技术选型建议

| 模块 | 建议方案 |
|------|---------|
| 客户端框架 | Kotlin（原生Android）或 Flutter（后续可扩iOS） |
| 本地存储 | SQLite / Room |
| 后端服务 | Python (FastAPI) 或 Node.js |
| 云端数据库 | PostgreSQL / MySQL |
| 对象存储（视频） | 云厂商OSS（阿里云OSS / 腾讯云COS） |
| 大模型 | Anthropic Claude API 或其他适合的模型 |
| TTS | 云服务TTS API（讯飞/阿里云/Azure等） |
| ASR | 云服务ASR API（讯飞/阿里云/Azure等） |
| 向量数据库（RAG） | ChromaDB / Milvus / 云厂商向量检索服务 |
| 推送服务 | Firebase / 极光推送 / 个推 |

### 4.3 云端知识库（RAG）设计

**知识库内容来源：**
- 腰椎间盘突出症诊疗指南
- McKenzie疗法核心原则
- 权威机构（如澳洲脊柱康复协会）的运动建议
- 运动康复学术文献中的训练方案
- 各动作的生物力学分析

**工作流程：**
1. 将文献资料分段处理，生成向量嵌入存入向量数据库
2. 当AI需要生成训练计划或回答专业问题时，先用用户问题/上下文在向量库中检索相关片段
3. 将检索到的片段拼入大模型的System Prompt或上下文中
4. 大模型基于这些专业资料生成回答

**知识库更新：** 开发者定期补充新的文献资料，更新向量数据库，无需用户更新App。

## 七、非功能性需求

### 7.1 性能要求

- App启动时间：冷启动 < 3秒
- 视频播放延迟：< 1秒（已缓存/下载的视频）
- AI语音响应延迟：< 2秒（从用户说完到AI开始回复）
- 本地数据操作：< 500ms

### 7.2 兼容性

- 支持Android 8.0及以上版本
- 适配主流分辨率（720p、1080p、2K）
- 适配横竖屏（训练播放界面支持横屏）

### 7.3 可用性

- 训练核心流程离线可用（AI功能除外）
- 操作步骤简洁，从打开App到开始训练不超过3步
- 字体大小适中，关键按钮大而明显（训练中需要大按钮操作）

### 7.4 安全与隐私

- 数据传输全程HTTPS加密
- 用户敏感数据（个人运动档案）本地加密存储

- 提供隐私政策和用户协议

## 八、风险与注意事项

### 8.1 法律合规风险

- 严格保持运动健身类App定位，避免涉及医疗诊断和治疗建议
- 免责声明必须完善且用户明确知情同意
- 不在App内展示医学文献原文或提供疾病诊断功能
- 健康数据处理符合相关法律法规

### 8.2 用户安全风险

- 训练前状态确认不可跳过
- 禁忌动作严格过滤，不可出现在任何自动生成的训练计划中
- AI不得给出超出运动健身范围的任何建议
- 用户反馈疼痛时，必须优先建议停止训练并就医

### 8.3 技术风险

- 大模型API成本需持续监控，Token限额需根据用户增长动态调整
- 语音识别在嘈杂环境或方言场景下准确率可能不足，需考虑备用文字输入方案
- 视频文件体积需优化压缩，避免占用过多用户手机存储
- 离线/在线数据同步冲突处理需设计好策略

### 8.4 内容风险

- 动作库中的动作需经过专业康复知识验证
- AI生成的训练计划需在合理范围内（通过Prompt约束和知识库支撑）
- 排行榜设计避免诱导过度训练（不以训练强度排名，只以天数排名）
