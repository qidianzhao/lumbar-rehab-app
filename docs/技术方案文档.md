## 一、技术栈总览

| 层级 | 技术选型 | 版本要求 | 选型理由 |
|------|---------|---------|---------|
| 客户端框架 | React Native + Expo | Expo SDK 52+ | AI代码生成质量最高、环境搭建最简单、跨平台 |
| 客户端语言 | TypeScript | 5.0+ | 类型安全减少运行时错误，AI生成TS代码质量优于纯JS |
| 客户端导航 | Expo Router | 最新稳定版 | 基于文件系统的路由，结构直观 |
| 客户端本地存储 | expo-sqlite | 最新稳定版 | Expo官方维护，无需eject |
| 客户端状态管理 | Zustand | 4.x | 轻量、API简单，比Redux代码量少60% |
| 后端框架 | Python + FastAPI | Python 3.11+, FastAPI 0.100+ | AI生成Python最强、自带API文档、异步支持好 |
| 后端ORM | SQLAlchemy + Alembic | 2.0+ | 数据库迁移管理成熟 |
| 云端数据库 | PostgreSQL | 14+ | 阿里云RDS直接支持，JSON字段支持好 |
| 缓存 | Redis | 7.0+ | Session管理、接口限流、排行榜 |
| 对象存储 | 阿里云OSS | - | 视频文件、用户导出PDF、分享图片 |
| CDN | 阿里云CDN | - | 视频分发加速 |
| 大模型 | DeepSeek V4 | deepseek-reasoner / deepseek-chat | 推理能力强、中文优秀、API兼容OpenAI格式 |
| TTS | 讯飞语音合成 | WebAPI | 中文语音自然度最佳 |
| ASR | 讯飞语音识别 | WebAPI | 中文识别准确率最高 |
| 向量数据库 | ChromaDB | 0.4+ | 轻量嵌入式，够用 |
| 短信服务 | 阿里云短信 | - | 注册验证码 |
| 推送服务 | 极光推送 (JPush) | - | 国内Android推送最稳定 |
| 容器化 | Docker + Docker Compose | - | 后端部署标准化 |
| 服务器 | 阿里云ECS | 2核4G起步 | MVP阶段够用 |

## 三、第三方服务配置

### 3.1 DeepSeek V4（大模型）

**用途：** 训练计划生成、体能评估分析、训练中AI对话、阶段报告生成

**接入方式：** OpenAI 兼容 REST API（`openai` Python SDK 直接可用）

**关键配置：**
- API Base URL: `https://api.deepseek.com`
- 模型选择:
  - `deepseek-reasoner`：开启思考链，用于体能评估、训练计划生成、阶段报告等复杂推理任务
  - `deepseek-chat`：快速对话，用于训练中问答、不适评估、鼓励话语
- 封装位置: `backend/app/services/deepseek_service.py`
  - `chat_with_reasoning(messages)` → 调用 `deepseek-reasoner`
  - `chat_fast(messages)` → 调用 `deepseek-chat`

**成本预估（MVP阶段，100用户）：**
- deepseek-reasoner: 约￥0.14/千tokens（输入），每次计划生成约3000 tokens ≈ ￥0.4
- deepseek-chat: 约￥0.014/千tokens，训练中对话每轮约500 tokens ≈ ￥0.007
- 每用户每天约1次训练 × 20轮对话 ≈ ￥0.5/用户/天
- 100用户/月 ≈ ￥1500/月

### 3.2 讯飞语音服务

**TTS（文字转语音）：**
- 用途：AI教练语音播报
- 接口：WebSocket流式合成
- 发音人：推荐`xiaoyan`（女声自然）或`aisjiuxu`（男声沉稳）
- 采样率：16kHz
- 免费额度：新用户500次/天（够MVP测试）

**ASR（语音识别）：**
- 用途：用户语音回复识别
- 接口：WebSocket实时转写
- 语言：中文普通话
- 免费额度：新用户500次/天

**注意：** 讯飞的WebSocket接口需要在后端中转，不能从客户端直连（否则暴露API密钥）。

### 3.3 阿里云服务

**ECS服务器：**
- 配置：2核4G、40G SSD、5Mbps带宽
- 地域：华东2（上海）
- 系统：Ubuntu 22.04
- 预估费用：约￥200-300/月（包年更便宜）

**RDS PostgreSQL：**
- 配置：基础版 1核2G、20G存储
- 预估费用：约￥100-150/月

**OSS对象存储：**
- Bucket：lumbar-rehab-app（私有读写）
- 目录结构：`videos/`、`exports/`、`share-cards/`
- CDN绑定：视频目录开启CDN加速
- 预估费用：存储￥0.12/GB/月 + 流量￥0.25/GB

**短信服务：**
- 用途：注册/登录验证码
- 费用：￥0.045/条
- 需要先申请短信签名和模板审核

**Redis：**
- 可以先用ECS上Docker部署的Redis
- 用户量大了再迁到阿里云Redis

### 3.4 极光推送 (JPush)

- 用途：训练提醒、久坐提醒
- 免费版支持：无限设备、基础推送功能
- MVP阶段免费版完全够用

## 四、关键技术方案

### 4.1 认证方案

**方案：手机号 + 验证码登录，JWT Token认证**

流程：
1. 客户端发送手机号到 `/auth/send-code`
2. 后端通过阿里云短信发送6位验证码，存入Redis（5分钟过期）
3. 客户端发送手机号+验证码到 `/auth/login`
4. 后端验证通过后，生成JWT Token（access_token有效期7天，refresh_token有效期30天）
5. 客户端将token存入expo-secure-store（加密存储）
6. 后续请求在Header中携带 `Authorization: Bearer {access_token}`

**为什么不做密码：** 手机验证码登录对用户更简单，你也不需要处理密码加密、找回密码等复杂逻辑。

**微信登录（可选，MVP可不做）：** 需要申请微信开放平台开发者账号和移动应用审核，流程较长，建议MVP先只做手机号登录。

### 4.2 AI语音互动方案

**整体流程：**

```
用户说话 → 客户端录音 → 音频上传后端 → 讯飞ASR识别为文字
    → 文字 + 训练上下文 发送给 DeepSeek V4 (deepseek-chat) → 生成回复文字
    → 回复文字 发送给 讯飞TTS → 生成音频流
    → 音频流返回客户端 → 播放AI语音
```

**延迟优化策略：**
1. ASR使用流式识别：用户说话过程中就开始识别，不用等说完
2. 大模型使用流式输出：第一个字生成就开始发TTS
3. TTS使用流式合成：收到部分文字就开始合成，边合成边播放
4. 整体延迟目标：用户说完 → AI开始说话 < 2秒

**离线降级：** 无网络时隐藏语音互动按钮，显示提示"AI教练需要联网使用"。训练视频播放和计时功能不受影响。

### 4.3 RAG知识库方案

**知识库构建流程：**
1. 收集权威康复文献（PDF/文字资料）
2. 用Python脚本将文献分段（每段300-500字）
3. 调用 DeepSeek Embedding API 生成向量
4. 存入ChromaDB

**检索流程：**
1. 当AI需要生成训练计划或回答专业问题时
2. 将用户上下文作为查询，在ChromaDB中检索Top-5相关片段
3. 将片段拼入大模型的System Prompt
4. 大模型基于这些专业资料生成回答

**知识库更新：** 开发者本地更新文献 → 重新运行build_index.py → 将新的ChromaDB数据目录上传到服务器。

### 4.4 离线方案

**本地数据库同步策略：**

客户端SQLite存储：
- 训练计划（完整缓存当前阶段的所有课程）
- 训练记录（每次训练完成后本地先存）
- 打卡记录（本地先存）
- 动作库基本信息（名称、描述、要点，不含视频）

同步机制：
- 每条本地数据有`sync_status`字段：`pending`/`synced`
- 联网时自动将`pending`数据上传到服务器
- 冲突策略：以服务器数据为准（因为用户不会在多设备同时使用）

**视频离线缓存：**
- 使用expo-file-system下载视频到本地
- 下载管理：按当前训练计划批量下载
- 存储管理：显示已占用空间，支持清除缓存

### 4.5 训练报告PDF生成

**方案：后端生成**

工具：Python的`reportlab`或`weasyprint`库

流程：
1. 客户端请求 `/export/pdf`，传入时间范围
2. 后端查询该时段所有训练数据
3. 后端生成PDF文件，上传到OSS
4. 返回OSS下载链接给客户端
5. 客户端调用系统分享功能分享文件

### 4.6 分享卡片生成

**方案：后端生成图片**

工具：Python的`Pillow`库

流程：
1. 客户端请求 `/share/card`，传入分享类型（训练报告/打卡记录）
2. 后端用Pillow绘制卡片图片（模板+数据填充）
3. 上传OSS，返回图片URL
4. 客户端调用expo-sharing调起系统分享

## 七、开发顺序建议

基于模块依赖关系，建议按以下顺序开发：

### 第一阶段：基础骨架（1-2周）

1. **后端项目搭建** → FastAPI项目结构、数据库连接、JWT认证
2. **客户端项目搭建** → Expo项目结构、页面路由、Axios封装
3. **用户认证流程** → 手机号登录（后端+客户端联调）
4. **个人运动档案** → CRUD接口 + 前端表单页面

### 第二阶段：核心训练流程（2-3周）

5. **动作库** → 后端动作数据接口 + 客户端动作列表和详情页
6. **视频播放器** → 跟练播放器组件（视频播放+进度控制+组间休息倒计时）
7. **训练计划管理** → AI生成计划接口 + 计划展示页面
8. **训练会话** → 开始训练→播放视频→记录完成情况→结束训练的完整流程

### 第三阶段：AI互动与评估（2-3周）

9. **AI对话接口** → DeepSeek API对接 + Prompt设计
10. **TTS/ASR对接** → 讯飞语音服务对接
11. **语音互动组件** → 客户端录音+播放AI语音
12. **体能测试** → 测试流程 + AI评估 + 结果展示

### 第四阶段：记录与社交（1-2周）

13. **训练记录与报告** → 单次报告 + 阶段报告
14. **打卡与排行榜** → 打卡日历 + 排行榜
15. **数据导出** → PDF报告生成
16. **社交分享** → 分享卡片生成

### 第五阶段：完善与上线（1-2周）

17. **离线模式** → 本地数据库同步 + 视频缓存
18. **推送通知** → 训练提醒 + 久坐提醒
19. **Token控制** → 限流 + 用量统计
20. **部署上线** → ECS部署 + 域名SSL + 应用商店提交
