## 一、数据库总览

### 1.1 表清单

| 序号 | 表名 | 中文名 | 说明 | 客户端本地缓存 |
|------|------|--------|------|--------------|
| 1 | users | 用户表 | 基本账号信息 | 否 |
| 2 | health_profiles | 运动档案表 | 用户个人运动健康档案 | 是（当前用户） |
| 3 | actions | 动作库表 | 所有训练动作的基础数据 | 是（全量） |
| 4 | assessments | 体能测试表 | 体能测试记录 | 是（当前用户） |
| 5 | assessment_items | 测试项目明细表 | 单次测试中每个动作的得分 | 是（当前用户） |
| 6 | training_plans | 训练计划表 | AI生成的训练计划 | 是（当前计划） |
| 7 | plan_days | 计划日课程表 | 每天的训练课程安排 | 是（当前计划） |
| 8 | plan_day_actions | 课程动作表 | 每天课程包含的具体动作 | 是（当前计划） |
| 9 | training_sessions | 训练会话表 | 每次训练的整体记录 | 是（全量） |
| 10 | training_records | 训练动作记录表 | 每次训练中每个动作的完成情况 | 是（全量） |
| 11 | checkins | 打卡表 | 每日打卡记录 | 是（全量） |
| 12 | pain_logs | 不适记录表 | 训练前的不适/疼痛记录 | 是（全量） |
| 13 | ai_chat_logs | AI对话日志表 | AI互动的对话记录 | 否 |
| 14 | token_usage | Token用量表 | 每日API调用量统计 | 否 |
| 15 | sms_codes | 短信验证码表 | 登录验证码（Redis更合适，此表为备用） | 否 |

### 1.2 ER关系概览

```
users (1) ──── (1) health_profiles
  │
  │ (1:N)
  ├──── assessments (1) ──── (N) assessment_items
  │
  ├──── training_plans (1) ──── (N) plan_days (1) ──── (N) plan_day_actions
  │
  ├──── training_sessions (1) ──── (N) training_records
  │
  ├──── checkins
  │
  ├──── pain_logs
  │
  ├──── ai_chat_logs
  │
  └──── token_usage

actions（独立表，被 plan_day_actions、training_records、assessment_items 引用）
```

## 三、客户端本地数据库（SQLite）

客户端使用expo-sqlite存储需要离线可用的数据。表结构与云端基本一致，但增加了`sync_status`字段用于同步管理。

### 3.1 客户端需要缓存的表

| 表 | 缓存策略 | 同步方向 |
|----|---------|---------|
| health_profiles | 缓存当前用户的档案 | 双向（编辑后上传，登录时下载） |
| actions | 全量缓存动作库基本信息 | 服务器→客户端（只读） |
| training_plans + plan_days + plan_day_actions | 缓存当前执行的计划 | 服务器→客户端（计划由服务器生成） |
| training_sessions + training_records | 全量缓存 | 客户端→服务器（先本地存再上传） |
| checkins | 全量缓存 | 客户端→服务器 |
| pain_logs | 全量缓存 | 客户端→服务器 |

### 3.2 同步机制

每条需要同步的记录都有`sync_status`字段：
- `pending`：本地新增或修改，待上传
- `synced`：已与服务器同步

**同步流程：**
1. 应用启动时 → 检查是否有网络
2. 有网络 → 上传所有`pending`状态的记录
3. 上传成功 → 更新本地`sync_status`为`synced`
4. 下载服务器上的最新数据（计划变更、动作库更新等）
5. 无网络 → 使用本地数据，所有新记录标记为`pending`

## 四、Redis数据结构

| Key格式 | 类型 | TTL | 用途 |
|---------|------|-----|------|
| `sms:{phone}` | STRING (验证码) | 5分钟 | 短信验证码存储 |
| `token_usage:{user_id}:{date}` | HASH | 24小时 | 当日Token用量计数 |
| `rate_limit:{user_id}:{endpoint}` | STRING (计数) | 1分钟 | 接口限流计数 |
| `leaderboard:week:{year}:{week}` | SORTED SET | 7天 | 周排行榜 |
| `leaderboard:month:{year}:{month}` | SORTED SET | 31天 | 月排行榜 |
| `leaderboard:year:{year}` | SORTED SET | 366天 | 年排行榜 |
| `session:{session_id}:context` | STRING (JSON) | 2小时 | 训练会话中AI对话上下文 |

**排行榜详细说明：**
- 使用Redis SORTED SET，score为训练天数
- 每次用户打卡时更新对应排行榜的score
- 查询排行榜使用ZREVRANGE（降序取top N）
- 查询用户排名使用ZREVRANK
